## What to build

A provider-agnostic AI gateway package that is the only door between DROP Studio OS and any
model provider (12 §1). All five machines and every specialized agent will eventually call
`generateStructured`; in Release 0 the only adapter is a deterministic mock that replays
fixtures, and that is enough to run the entire pipeline, because the gateway's contract — not
any provider's SDK — is what the runtime consumes.

The tracer-bullet vertical slice: a fixture structured-generation request travels through the
real executor harness (Seam 1), the gateway resolves a versioned model profile from
`configs/models` and a versioned prompt reference from configuration (ADR-0011 D2.3), the mock
adapter returns a raw response, the pipeline validates it against the exact JSON Schema version,
the parsed payload is stored as artifact-version content with a validation record, the raw
response is stored separately under restricted access with only a reference on the stage
attempt (06 §9.2), and usage is recorded per attempt (12 §16). Flip the configuration to "no
provider" and the same call returns a typed `PROVIDER_CONFIGURATION_REQUIRED` result — nothing
crashes, and everything that is not AI keeps working (12 §4, 00 §4). That is what is demoable
when this ticket is done.

Key mechanics, in bundle order:

1. **Gateway boundary** (12 §1). `AiGateway.generateStructured<I, O>` with request fields for
   model profile reference, prompt version, input artifact IDs, output JSON Schema, budget and
   correlation IDs. Adapters are registered per provider key; domain code sees only the gateway.
   A static dependency rule enforces that no provider SDK is importable outside the adapter
   directory (05 §4).
2. **Model profiles** (12 §2). Load versioned profiles (profile_id, version, task_class,
   provider_adapter, model_identifier, limits, cost ceiling, timeout, fallback profile,
   data_transmission_class, status) from `configs/models`. No "Claude" or other provider string
   in machine contracts.
3. **Structured output and repair** (12 §3). Validate input with Zod, request schema-constrained
   output, preserve the raw response separately, parse and validate with the exact schema
   version, perform exactly one repair request carrying the validation errors on malformed
   output, and return `MALFORMED_OUTPUT_FINAL` if repair fails. Never auto-approve or invent
   fields. Semantic/hard-rule validators run downstream, after schema validation.
4. **Configuration-required detection** (12 §4, 11 §7). When no valid live profile/credential
   exists, return the typed `PROVIDER_CONFIGURATION_REQUIRED` outcome. The runtime maps it to
   `WAITING_FOR_INPUT` with reason code per ADR-0012 — this ticket only guarantees the typed,
   non-throwing, non-retry-storming result. The gateway never assumes a proxy, VPN or bypass.
5. **Usage and redaction** (12 §16; ADR-0016). Every attempt records token/cost usage, failure
   class, error code and safe diagnostic. Credentials are resolved server-side at call time and
   are provably absent from logs, prompts and stored raw responses.

## Blocked by

0.3 (contracts), 0.4 (schemas). Not blocked by 0.8: the gateway consumes versioned prompt
*references*; R0 fixtures may seed configuration directly, and full registry resolution wires in
when 0.8 lands (coordinate in handoff).

## Acceptance criteria

- [ ] **AC-9.1 Mock structured output validates and stores** (restored R0 exit criterion,
  ADR-0011 D2.1): a fixture run through the Seam 1 harness produces an artifact version whose
  payload passed the exact JSON Schema version, plus a stored validation record.
  `pnpm test` → tests/workflow/gateway/structured-output.
- [ ] **AC-9.2 Raw response separation** (12 §3; 06 §9.2): the raw mock response is persisted
  separately from the parsed artifact; the stage attempt holds only a reference; no artifact
  payload or gateway result object contains the raw response. Seam 1 assertion plus a negative
  repository-guard test proving unprivileged read paths are refused.
- [ ] **AC-9.3 One bounded repair, success path** (12 §3; 14 §6 scenario 5): malformed fixture →
  exactly one repair request containing the validation errors → valid output; result classified
  `MALFORMED_OUTPUT_REPAIRED`; attempt usage recorded for both calls. Unit + Seam 1.
- [ ] **AC-9.4 One bounded repair, failure path** (12 §3; 14 §6 scenario 6): repair also
  malformed → `MALFORMED_OUTPUT_FINAL`, no second repair, no invented fields; the harness shows
  the consumer can mark the stage `FAILED_FINAL`. Unit + Seam 1.
- [ ] **AC-9.5 Provider-required state** (12 §4; ADR-0012): with no valid profile/credential the
  gateway returns typed `PROVIDER_CONFIGURATION_REQUIRED` without throwing and without retry;
  registries, artifacts and manual flows in the harness remain unaffected. Seam 1.
- [ ] **AC-9.6 Prompt and profile versions come from configuration** (ADR-0011 D2.3; 12 §2, 12 §5):
  changing only configuration changes the resolved prompt/profile version recorded on the
  attempt, with no code change; a request lacking a versioned prompt reference is rejected with
  a typed error. Unit + contract test.
- [ ] **AC-9.7 Usage accounting** (12 §16; 06 §9.2): every attempt (including the repair call)
  stores token/cost usage, failure class and safe diagnostic via the stage-attempt repository.
  Seam 1.
- [ ] **AC-9.8 Provider SDK boundary** (12 §1; 05 §4): the dependency-boundary check fails on a
  committed fixture violation (provider SDK import outside adapters) and passes on the real
  tree. `pnpm lint` (or the dedicated boundary script wired into it).
- [ ] **AC-9.9 Credential redaction** (ADR-0016; 14 §9): a live-like adapter fixture configured
  with a dummy credential produces logs, raw-response records and error payloads containing no
  credential material. Unit redaction test.
- [ ] **AC-9.10 Checks green** (16 §7): `pnpm typecheck && pnpm lint && pnpm test && pnpm build`
  pass at the repo root.
