## What to build

The reproducibility spine of the system: every pipeline run carries an immutable manifest that
freezes exactly which workflow version, registry versions, schemas, model profiles, policies
and budgets produced it (07 §6; 12 §5) — and a first, contract-stable way to ask "what differed
between these two runs?" (15 §2 row 0.11). Release 6's exit criterion — differences between two
runs are explainable from manifests and graph state (15 §8) — is only achievable if this ticket
freezes enough, correctly, now.

The tracer-bullet vertical slice: create two synthetic runs of the same published workflow with
one deliberate configuration change between them (a bumped prompt version). Inspect the first
run's manifest and see every 07 §6 field frozen and resolvable; try to UPDATE it and watch the
database refuse; call `GET /api/v1/studio/runs/compare?leftRunId=…&rightRunId=…` and get back a
typed diff whose only manifest difference is that prompt version. Then break one registry
reference on purpose and watch run creation fail closed before READY.

Key mechanics:

1. **Complete the freeze** (07 §6). Ticket 0.10 ships run creation with a minimal atomic
   freeze; this ticket completes the manifest to the full field list. Every reference is a real
   versioned row: the constitution/rule/prompt/example registries exist as versioned tables
   with publish flows per ADR-0015 (schema 0.4, flows 0.8) — which is precisely why this ticket
   now depends on 0.8 (ADR-0014 dependency correction; the original 15 §2 row hid this).
2. **Executor/validator identity** (ADR-0015). Executors and validators are code, not rows;
   their identity is frozen as code-version + checksum in the manifest so a historical run can
   state exactly which implementation ran, and drift is detectable.
3. **Fail closed** (07 §6; ADR-0012). If any required version cannot be resolved at run
   creation, creation fails with MANIFEST_RESOLUTION_FAILED, no partial manifest row survives,
   and the run never reaches READY. No default, no fallback, no "resolve later".
4. **Immutability at all three layers** (06 §11). Application guard, database trigger/policy on
   studio.run_manifests, and negative tests at the repository and HTTP seams.
5. **Canonical comparison contract** (ADR-0014). The read-only endpoint uses
   `leftRunId`/`rightRunId` (10 §6). The 04 §5 `?left=&right=` naming is superseded — the
   endpoint rejects legacy names with a typed error naming the canonical parameters, so no
   second contract can grow silently. The result is a field-level manifest diff (workflow
   version/checksum, each registry version, model profiles, budgets, policies) plus per-run
   terminal status and stage-state summary — data for the R6 UI, not the UI itself.

0.8 (versioned registries with publish flows — manifest references need real targets;

## Acceptance criteria

- [ ] **AC-11.1 Full freeze** (07 §6; 12 §5): a synthetic run's manifest contains every 07 §6
  field, non-null and resolving to an existing versioned row — workflow definition/version +
  checksum, constitution version, rule registry version, prompt and example versions,
  machine/stage schema versions, model profiles + gateway config version, input artifact
  versions, approval policies, budgets, initiating actor. Seam 1 + DB FK test (ADR-0015).
- [ ] **AC-11.2 Executor/validator identity** (ADR-0015): the manifest records code-version +
  checksum for every executor/validator the run references, and the test recomputes and matches
  the checksum. Seam 1.
- [ ] **AC-11.3 Fail-closed creation** (07 §6; ADR-0012): with one required registry version
  made unresolvable, run creation fails with MANIFEST_RESOLUTION_FAILED, leaves no partial
  manifest row, and the run never reaches READY. Seam 1 negative test.
- [ ] **AC-11.4 Immutability** (06 §9.2, §11; 17 §4): UPDATE/DELETE against run_manifests is
  rejected at the DB layer and at the repository guard; there is no mutating HTTP surface, and
  a crafted mutation attempt through the API returns the immutability error. tests/db +
  Seam 2 negative tests.
- [ ] **AC-11.5 History survives new publications** (14 §6 sc.12): after publishing a new
  workflow version and new registry versions, the historical run's manifest is byte-identical
  and a new run freezes the new versions. Seam 1.
- [ ] **AC-11.6 Canonical comparison endpoint** (10 §6; ADR-0014): GET
  /api/v1/studio/runs/compare?leftRunId=&rightRunId= returns a RunComparisonResultV1 that
  validates against the contract; for the two-run fixture the manifest diff contains exactly
  the deliberately changed prompt version and nothing else (seed for 15 §8 R6 exit). Seam 2 +
  contract test.
- [ ] **AC-11.7 Legacy names rejected** (10 §6 canonical shape): ?left=&right= receives
  COMPARISON_PARAMETERS_INVALID with the canonical parameter names in the error payload —
  proven by test so the 04 §5 naming cannot silently re-enter. Seam 2.
- [ ] **AC-11.8 Tenant isolation** (14 §9): comparing a run in the caller's workspace against a
  run in another workspace returns COMPARISON_TARGET_NOT_FOUND with no metadata about the
  foreign run; direct manifest reads across workspaces behave identically. Seam 2 security
  test.
- [ ] **AC-11.9 Checks green** (16 §7): `pnpm typecheck && pnpm lint && pnpm test &&
  pnpm test:db && pnpm build` pass.
