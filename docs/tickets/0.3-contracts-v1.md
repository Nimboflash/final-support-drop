## What to build

The contract freeze that opens every parallel lane (15 §11). This ticket turns docs 06/07/10/11
— as repaired by ADR-0012/0013/0014/0015 — into executable Zod 4 schemas with schema ID/version
envelopes (05 §2), so that 0.4 (database), 0.10 (runtime), 0.13 (dashboard) and 0.16 (API band)
all consume one authority instead of re-reading prose.

The centerpiece is the complete state machine. Doc 07 §3.1's outline is the base, and the
ADR-0012 repairs are applied here, not restated as problems: entries into PAUSED
(PAUSE_RUN from RUNNING|READY|QUEUED at run scope), CANCELLED reachable from every non-terminal
state, SKIPPED produced only by condition-false edges or the governed SKIP_STAGE command,
SUCCEEDED -> SUPERSEDED only through a later run/version relationship (07 §3.1). The run-level
enum and the stage-to-run aggregation rule are the ADR-0012 decisions encoded as exported typed
data; packages/pipeline will execute them in Ticket 0.10 but can never redefine them.
WAITING_FOR_INPUT carries a reason-code enum whose members include
PROVIDER_CONFIGURATION_REQUIRED (11 §7), collapsing the doc 11/doc 07 state-model mismatch into
one canonical model.

The command set applies ADR-0013: gate verbs are gone from the runtime command enum, and a
negative fixture proves it. SUBMIT_INPUT's payload schema references the node-definition
manual_fallback flag so the "can a human satisfy an automated stage" question has exactly one
answer (ADR-0012): only when the published definition allows it.

Workflow definition contracts encode 06 §9.1 and 07 §4/§11/§13 fully — including loop-edge
budgets and a WorkflowValidationResult type with one finding kind per 07 §13 check — while
keeping layout strictly cosmetic (ADR 0010). Program and Weekly Lens envelopes encode 06
§3.3-3.4 with ADR-0015 status vocabularies and the Lens structural refinements. The event
taxonomy ships complete per ADR-0014 so Ticket 0.16's SSE stream and Ticket 0.13's execution
view are born against terminal-aware events rather than the truncated 10 §9 list.

**Demoable when done:** `pnpm test` runs the contract suite green; a reviewer can open one
generated JSON Schema file per entity and see the whole state machine, and a fixture showing
`APPROVE_GATE` being rejected as a run command.

## Acceptance criteria

- [ ] **AC-1** Every exported schema has at least one valid and one invalid fixture exercised in tests/contract; the suite runs under `pnpm test` (14 §3 layer 1). *Seam: contract tests.*
- [ ] **AC-2** Exact-membership tests: the stage enum equals the 14 states of (07 §3) and the run enum equals the 9 ADR-0012 states — no additions, omissions or renames. *Seam: contract tests.*
- [ ] **AC-3** Transition-table tests verify each ADR-0012 repair: PAUSED is enterable exactly from RUNNING|READY|QUEUED via PAUSE_RUN and exits only to READY (RESUME_RUN) or CANCELLED; every non-terminal state has a CANCEL_RUN path to CANCELLED; SKIPPED is producible only by CONDITION_FALSE edge outcome or SKIP_STAGE; FAILED_FINAL, CANCELLED, SKIPPED and SUPERSEDED have no outgoing runtime transitions; SUCCEEDED transitions only to SUPERSEDED via a later run/version relationship (07 §3.1). *Seam: contract property tests.*
- [ ] **AC-4** The aggregation rule is total and deterministic: a property test maps arbitrary non-empty multisets of stage states to exactly one run status, matching the ADR-0012 precedence; an empty or unknown input fails typed. *Seam: contract property tests.*
- [ ] **AC-5** The run-command schema rejects APPROVE_GATE, REQUEST_CHANGES and ESCALATE_GATE payloads (negative fixtures) and accepts the eight permitted commands with mandatory idempotency key, reason and expectedRowVersion (07 §12; 10 §3; ADR-0013). *Seam: contract tests.*
- [ ] **AC-6** WorkflowNodeDefinition includes manual_fallback (default false); a SUBMIT_INPUT fixture against a non-manual_fallback automated stage fails schema-level validation where structurally expressible, and the reason-code enum includes PROVIDER_CONFIGURATION_REQUIRED bound to WAITING_FOR_INPUT (ADR-0012; 11 §7). *Seam: contract tests.*
- [ ] **AC-7** The event-taxonomy enum contains every 10 §9 name plus run.completed, run.failed, run.cancelled, run.paused, run.resumed, stage.skipped, stage.cancelled and heartbeat (ADR-0014); the SSE envelope schema matches 10 §8.1 with sequence/resume fields; snapshot test over the enum guards against silent removal. *Seam: contract tests.*
- [ ] **AC-8** Project, Program, WeeklyLens, Request and CalendarItem status enums equal the ADR-0015 enumerations exactly (exact-membership test against a fixture transcribed from ADR-0015); WeeklyLens refinements reject end <= start and APPROVED without context-artifact and Bible-version references (06 §3.4). *Seam: contract tests.*
- [ ] **AC-9** The layout schema accepts coordinates/group dimensions/viewport only and rejects any node/edge semantic field; a test asserts zero key overlap with semantic schemas beyond identity keys (06 §9.1; ADR 0010). *Seam: contract tests.*
- [ ] **AC-10** JSON Schema generation succeeds for every v1 schema and output is snapshot-tested (05 §3). *Seam: contract tests.*
