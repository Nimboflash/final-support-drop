# Ticket 0.14 — S3-compatible storage

## What to build

The tracer-bullet slice for bytes. When this ticket is done, an authorized user uploads a file
through the API; the platform sniffs and allowlists its content type, enforces the size limit,
normalizes the filename, streams it into a private MinIO bucket, records its checksum against the
0.7 artifact registry row, and can hand back the same bytes two ways: a server-streamed
authorized read, or a short-lived, single-object access grant. A generated preview of that
artifact is written to the isolated preview prefix and served from the restricted preview origin
with its own CSP — provably without dashboard cookies. Stopping the MinIO container flips
`/health/ready` to not-ready for file operations while the dashboard stays readable.

Demoable when done: R0 vertical demo step 6 (15 §2) — inspect an artifact version — serves real
stored bytes with verified checksums, and the Release 6 restore drill (13 §7) has the checksum
substrate it needs.

Constraints that shape the build:

- All storage access goes through the `ObjectStorage` interface (12 §14); nothing imports an S3
  SDK type outside `packages/storage` (05 §4).
- Deployment must remain vendor-portable: managed S3 on an Iranian vendor is acceptable only
  through this same adapter with a documented export/restore path (13 §2).
- Per ADR-0016, the MinIO image is pulled from the mirror-capable configuration recorded in the
  doc 13 amendment — the build must not silently depend on Docker Hub availability — and no
  outbound fetch made by storage code attaches credentials.

## Acceptance criteria

- [ ] Upload through the API stores the object in a private bucket and records size, content
      type and checksum on the artifact version row; a deliberately corrupted stream is rejected
      with a checksum-mismatch error and no registry row — Seam 2 integration test against MinIO.
- [ ] Read-back re-verifies the checksum; `head` returns metadata without moving bytes —
      integration test.
- [ ] `createAuthorizedAccess` grants expire (clock-advanced test) and are scoped to exactly one
      object; using a grant for another key or after expiry fails — security test (14 §9).
- [ ] Cross-workspace file fetch and preview access are denied with no data leakage — Seam 2
      tenant-isolation test (10 §12).
- [ ] Browser-visible payloads never contain long-lived storage credentials — Seam 2 response
      assertion (10 §11).
- [ ] Content-type allowlist rejects a file whose sniffed type contradicts its declared type;
      oversize upload rejected at the configured limit; unsafe filenames normalized — Seam 2.
- [ ] Preview objects land under the restricted preview prefix/bucket; the preview origin serves
      them with the stricter isolated CSP and requests from the preview context carry no
      dashboard session cookie — security e2e (14 §9 generated preview isolation).
- [ ] With MinIO stopped, `/health/ready` reports not-ready for file/artifact operations, web
      stays up, and the failure is a typed retryable error at the HTTP seam (13 §5) —
      integration test.
- [ ] Adapter conformance suite runs identically against MinIO and a second S3-compatible
      endpoint configuration to prove portability (13 §2) — integration test matrix.
- [ ] `pnpm typecheck && pnpm lint && pnpm test && pnpm build` green.
