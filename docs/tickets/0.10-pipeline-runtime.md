## What to build

The PostgreSQL-authoritative execution engine: load a published, immutable workflow version,
create a run whose manifest freezes atomically (fail-closed, 07 §6 — minimal fields here, full
contents arrive with 0.11), and drive stage runs through the **complete** state machine — the
one ADR-0012 finishes, not the doc 07 §3.1 outline that had no way into PAUSED, no producer for
SKIPPED and no path to CANCELLED from RUNNING. Redis/BullMQ carries only reconstructable
dispatch state (00 §4; ADR 0010 D4).

The tracer-bullet vertical slice is the machinery behind Release 0 demo steps 3, 4 and 7
(15 §2): start a synthetic three-node run with the mock executor, watch persisted events move
stages through queued/running/waiting/succeeded, pause and resume it, cancel a second run
mid-flight, skip a condition-false branch, then flush Redis and watch the reconciler finish the
remaining work from PostgreSQL alone. All of that is observable through persisted rows and the
snapshot query — no HTTP or UI required (0.16 and 0.13 layer those on).

Key mechanics:

1. **State machine** (07 §3.1 + ADR-0012). Implement the full transition table: the doc 07
   outline plus `RUNNING|READY|QUEUED → PAUSED` under PAUSE_RUN, `PAUSED → READY` under
   RESUME_RUN, `any non-terminal → CANCELLED` under CANCEL_RUN (RUNNING attempts cancel via the
   StageContext abortSignal, 07 §5), and `→ SKIPPED` from condition-false edges or governed
   manual skip. While a run is paused, no new attempt is dispatched. Illegal transitions are
   rejected inside the transaction, never patched over.
2. **Run-level aggregation** (ADR-0012). `pipeline_runs.status` uses the canonical enum
   DRAFT|QUEUED|RUNNING|WAITING_INPUT|WAITING_APPROVAL|PAUSED|SUCCEEDED|FAILED|CANCELLED and is
   derived from stage states by ADR-0012's precedence rule: CANCELLED > FAILED (a required
   FAILED_FINAL with no remaining bounded path) > PAUSED > WAITING_APPROVAL > WAITING_INPUT >
   RUNNING > QUEUED > DRAFT — and SUCCEEDED only when every required stage is
   SUCCEEDED|SKIPPED (evaluated last, per ADR-0012 D3). Implement exactly the ADR's table; the ADR, not this ticket, is the authority if
   they ever diverge.
3. **Commands** (07 §12 as amended by ADR-0013). Runtime set: START_RUN, PAUSE_RUN, RESUME_RUN,
   CANCEL_RUN, RETRY_STAGE, SUBMIT_INPUT, SKIP_STAGE (capability-gated, ADR-0012),
   CREATE_RERUN. APPROVE_GATE, REQUEST_CHANGES and ESCALATE_GATE do not exist here: approval
   decisions and escalation travel only through the approval-requests/decisions path
   (ADR-0013 D2; escalation is the approval policy's escalation_behavior, see 0.16). SUBMIT_INPUT
   may satisfy an AUTOMATED_STAGE only when the published node definition carries
   `manual_fallback: allowed` (ADR-0012) — this is the concrete manual-mode semantics 00 §4
   requires.
4. **Human gates** (07 §7; ADR-0013). A HUMAN_APPROVAL_GATE parks its stage in
   WAITING_FOR_APPROVAL with no long-running queue job, and resumes exactly once when the
   approval service emits approval.decided for the exact subject version.
5. **Outbox, idempotency, checkpoints, recovery** (07 §7; 06 §2.3). Stage-state change and
   outbox row commit in one transaction; the dispatcher (worker process, FOR UPDATE SKIP
   LOCKED) moves work to BullMQ; workers claim by stage-run ID + idempotency key and re-check
   durable state before working; checkpoints store completed durable steps only; duplicate
   delivery returns the recorded result or no-ops; on Redis loss a reconciler re-derives
   dispatch from `READY|QUEUED|FAILED_RETRYABLE` rows.
6. **Events** (10 §9 + ADR-0014). Persist the extended taxonomy — run.started/completed/failed/
   cancelled/paused/resumed and stage.queued/started/waiting_for_input/waiting_for_approval/
   succeeded/failed_retryable/failed_final/skipped/cancelled — with monotonic per-run
   sequence_number, schema version, actor and correlation IDs. Heartbeat is 0.16's transport
   concern and is never a persisted event.

## Acceptance criteria

- [ ] **AC-10.1 Happy synthetic run** (14 §6 sc.1; 07 §14): the fixture three-node workflow runs
  to run SUCCEEDED with every required stage SUCCEEDED|SKIPPED-under-allowed-condition; Seam 1.
- [ ] **AC-10.2 Pause and resume** (ADR-0012; ADR-0014): PAUSE_RUN against a run holding READY,
  QUEUED and RUNNING stages yields run PAUSED, zero new attempt dispatches while paused, and
  persisted run.paused; RESUME_RUN restores eligible stages and persists run.resumed; the run
  then completes. Seam 1.
- [ ] **AC-10.3 Cancel from every non-terminal shape** (ADR-0012; 14 §6 sc.9): CANCEL_RUN
  succeeds before start, during a queued stage, and during cancellable RUNNING execution (abort
  observed via abortSignal); stages record stage.cancelled, run records run.cancelled, and no
  further work dispatches. Seam 1.
- [ ] **AC-10.4 SKIPPED has producers** (ADR-0012): a condition-false edge marks the untaken
  branch SKIPPED with reason CONDITION_FALSE; SKIP_STAGE with the required capability records
  actor, acted-as role and reason and emits stage.skipped; SKIP_STAGE without the capability is
  rejected server-side. Integration seam + negative RBAC test.
- [ ] **AC-10.5 Aggregation matrix** (ADR-0012): a table-driven test over stage-state
  combinations proves pipeline_runs.status matches the ADR-0012 precedence rule for every row,
  including mixed WAITING/RUNNING and post-terminal shapes. Integration seam.
- [ ] **AC-10.6 Provider-required mapping** (ADR-0012; 12 §4): a gateway
  PROVIDER_CONFIGURATION_REQUIRED outcome parks the stage WAITING_FOR_INPUT with that reason
  code and no queue job, aggregates the run to WAITING_INPUT, and leaves manual commands
  usable. Seam 1.
- [ ] **AC-10.7 manual_fallback gating** (ADR-0012; 00 §4): SUBMIT_INPUT completes an
  AUTOMATED_STAGE flagged manual_fallback: allowed in the published definition, and is rejected
  with a typed error on an unflagged stage. Seam 1.
- [ ] **AC-10.8 Single approval write path** (ADR-0013; 14 §6 sc.3–4): the runtime command enum
  contains no APPROVE_GATE/REQUEST_CHANGES/ESCALATE_GATE; a decision- or escalation-shaped command is rejected with a typed
  error naming the approval endpoints; a gate parks with no queue job and resumes exactly once
  on approval.decided — a duplicated decision event does not resume it twice. Seam 1 +
  integration.
- [ ] **AC-10.9 Retry and repair wiring** (07 §8; 14 §6 sc.5–7): malformed-output
  repaired-once-succeeds and fails-after-one-repair land in the expected stage states;
  infrastructure failure reaches FAILED_RETRYABLE then follows the bounded profile to recovery
  or FAILED_FINAL. Seam 1.
- [ ] **AC-10.10 Budget escalation** (07 §8; 14 §6 sc.8): budget exhaustion produces the named
  escalation/block state and never silently continues. Seam 1.
- [ ] **AC-10.11 Outbox atomicity and duplicate safety** (07 §7; 14 §6 sc.11; 17 §4): fault
  injection between state write and dispatch shows stage state and outbox row commit or roll
  back together; replaying an outbox/queue delivery produces no duplicate attempts, events or
  artifacts. Integration + DB seams.
- [ ] **AC-10.12 Redis reconstruction** (07 §7; 14 §6 sc.10; 17 §4): FLUSHALL mid-run, run the
  reconciler, and the run completes from PostgreSQL state with no lost durable work and no
  duplicated results. Seam 1.
- [ ] **AC-10.13 Failed runs visible with stage states** (ADR-0011 D2.2): the snapshot query for
  a failed run returns run status FAILED plus per-stage states, failure classes and attempt
  counts — the exact shape 0.13's execution view consumes. Integration seam.
- [ ] **AC-10.14 Ordering, idempotency and checks** (06 §9.2; 07 §12; 16 §7): DB tests prove
  unique (run_id, sequence_number) and (run_id, idempotency_key); a duplicate command with the
  same idempotency key returns the first result; `pnpm typecheck && pnpm lint && pnpm test &&
  pnpm test:db && pnpm build` pass.
