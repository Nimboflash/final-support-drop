# Ticket 0.7 — Artifact and run registries: versions, provenance, run records and immutable manifests

## What to build

The durable memory of the system: the artifact registry and the run registry, plus the minimal
Project/Program rows and API that the R0 exit criteria actually require (ADR-0011). The doc 15 §2
row calls this the "Artifact and Machine Run registries"; per the recorded terminology
supersession (06 §9.2), the "Machine Run registry" IS `pipeline_runs`/`stage_runs`/
`stage_attempts`/`run_events` (06 §9.2) — no separate registry table is invented.

Artifacts get stable identity with immutable versions carrying the full 12 §12 record (producer,
input versions, frozen config versions, object reference, checksums, status, confidence), typed
provenance edges restricted to the nine 06 §10 relations, and validation records whose validator
identity is code-version + checksum (ADR-0015). Raw AI responses live in a separate restricted
namespace that can never be referenced as an approved artifact version (06 §7); the read
capability gate is 0.6's, the storage separation is this ticket's.

Run persistence applies ADR-0012 in full: `pipeline_runs.status` is DB-constrained to the
nine-value run enum, the complete stage transition table — including entry into PAUSED from
RUNNING|READY|QUEUED, SKIPPED produced by condition-false edges or governed manual skip, and
CANCELLED from any non-terminal state — ships as data with a validation function, and the
stage-to-run aggregation rule is a pure, exhaustively table-tested function. Ticket 0.10 wires
these into the running engine; this ticket makes it impossible to persist a state the model
doesn't define. `run_manifests` freeze the 07 §6 content list atomically and fail closed with
`MANIFEST_VERSION_UNRESOLVABLE` when any version cannot be resolved — against fixture registries
from `packages/testing` until 0.8 supplies real ones. `run_commands` persists only the ADR-0013
command set: gate verbs are structurally unrepresentable.

**Demoable when done:** a seed script plus curl sequence creates a Project, a versioned brief, a
Program row, then a synthetic run row with a frozen manifest and one artifact version with a
provenance chain back to its inputs — all inspectable via GET endpoints — and a PATCH against the
published artifact version or manifest is rejected at every layer.

## Blocked by

- **0.4** — studio schema tables must exist. Otherwise: **None — can start immediately** after
  0.4; authorization wiring upgrades in place once 0.6 merges.

## Acceptance criteria

- [ ] **AC1** (ADR-0011) A Project, brief version and Program can be created and read via
  `/api/v1/studio/projects|programs` with 06 §3 required fields and ADR-0015 status enums;
  `(project_id, version)` uniqueness on briefs holds; the Program creation FLOW is absent by
  design. — Seam 2, `tests/integration/studio/projects-programs.spec.ts`, `pnpm test`;
  `tests/db/artifacts/brief-unique.spec.ts`, `pnpm test:db`.
- [ ] **AC2** In-place mutation of an artifact_version is rejected at the HTTP seam (PATCH →
  `ARTIFACT_VERSION_IMMUTABLE`), at the repository seam, and by DB trigger on direct SQL —
  all three 06 §11 layers proven in one suite. —
  `tests/integration/studio/artifact-immutability.spec.ts` + `tests/db/artifacts/triggers.spec.ts`,
  `pnpm test`, `pnpm test:db`.
- [ ] **AC3** artifact_relations rejects any relation type outside the nine 06 §10 values; a
  fixture graph query returns a complete path from an approved artifact version to its source
  artifacts and run manifest (06 §10). — `tests/db/artifacts/provenance.spec.ts`, `pnpm test:db`.
- [ ] **AC4** No artifact endpoint or DTO can return a raw-response object or accept a
  raw-response reference as an artifact version (`RAW_RESPONSE_NOT_ARTIFACT`); security test
  attempts both directions. — `tests/security/artifacts/raw-response.spec.ts`, `pnpm test`.
- [ ] **AC5** Direct SQL inserting a pipeline_run or stage_run with a status outside the
  ADR-0012 / 07 §3 enums violates a CHECK constraint. — `tests/db/runs/status-enums.spec.ts`,
  `pnpm test:db`.
- [ ] **AC6** The transition validation function accepts every row of the ADR-0012 table
  (including RUNNING|READY|QUEUED→PAUSED, PAUSED→READY via resume, condition-false→SKIPPED,
  governed manual skip, every non-terminal→CANCELLED) and rejects a generated set of
  non-table transitions (`ILLEGAL_STAGE_TRANSITION`). — `tests/workflow/state/transitions.spec.ts`,
  `pnpm test`.
- [ ] **AC7** The stage-to-run aggregation function passes a table-driven suite covering: all
  succeeded/skipped → SUCCEEDED (07 §14), any PAUSED → PAUSED, any WAITING_* mapping, FAILED_FINAL
  → FAILED, cancellation propagation, and WAITING_INPUT for PROVIDER_CONFIGURATION_REQUIRED with
  reason code (ADR-0012). — `tests/workflow/state/aggregation.spec.ts`, `pnpm test`.
- [ ] **AC8** Manifest freeze is atomic (all-or-nothing in one transaction), the frozen record
  contains every 07 §6 item with executor/validator identity as code-version + checksum
  (ADR-0015), and removing one fixture registry version makes run creation fail closed with
  `MANIFEST_VERSION_UNRESOLVABLE`. — `tests/integration/studio/manifest-freeze.spec.ts`,
  `pnpm test`.
- [ ] **AC9** Concurrent event appends never violate (run_id, sequence_number) uniqueness and
  sequences have no gaps under the allocator; duplicate (run_id, idempotency_key) command insert
  is rejected. — `tests/db/runs/events-commands.spec.ts`, `pnpm test:db`.
- [ ] **AC10** (ADR-0013) Persisting a run_command with APPROVE_GATE, REQUEST_CHANGES or ESCALATE_GATE fails at
  contract validation and at the DB CHECK. — `tests/db/runs/command-set.spec.ts`, `pnpm test:db`.
