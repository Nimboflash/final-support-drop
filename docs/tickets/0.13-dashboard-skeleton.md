# Ticket 0.13 — Dashboard skeleton

## What to build

The tracer-bullet vertical slice for the operator surface. When this ticket is done, a seeded
Technical Maintainer signs into the Persian, RTL `/studio` shell (built on the 0.12 foundation),
opens `/studio/workflows`, sees the definition list with version statuses, opens a draft in the
generic React Flow editor, adds and configures nodes by drag/drop **or** by the form alternative,
saves the draft with optimistic concurrency, runs server validation and watches findings focus
their target node (08 §16). A second seeded Viewer opens the same definition and gets the
read-only TEMPLATE_READ view with no edit or publish affordances. Both users can open
`/studio/runs/[runId]/workflow` for the synthetic run produced by 0.10/0.16 and watch the
execution snapshot view apply live SSE events — including the repaired terminal, pause and skip
events added by ADR-0014 — with correct stale/reconnecting behaviour when the stream drops.

Demoable when done: the R0 vertical demo steps 1, 4 and 6 (15 §2) run through this UI —
create/edit a draft three-node workflow, watch live nodes move through
queued/running/waiting/succeeded (plus paused and cancelled per ADR-0012), and inspect
artifact/attempt/audit summaries in the inspector. Steps 2, 3 and 5 are driven through the 0.16
APIs this UI calls.

Constraints that shape the build:

- Workflow semantics stay separate from canvas coordinates and styling (00 §5); React Flow types
  never leak out of `packages/workflow-ui` (05 §4, 08 §2).
- Zustand holds ephemeral editor state only; TanStack Query holds server state; PostgreSQL is
  the durable authority (08 §8, ADR 0010).
- The approval-gate node CTA opens the standard approval sheet, which submits decisions to
  `POST /api/v1/core/approval-requests/:id/decisions` and nothing else. No `APPROVE_GATE` or
  `REQUEST_CHANGES` run command exists anywhere in this UI (ADR-0013; supersedes the run-command
  gate verbs listed in 07 §12).
- The execution view renders every state in the repaired enum — `PAUSED`, `SKIPPED`, `CANCELLED`
  included — and never uses colour as the only indicator (08 §5, ADR-0012).
- On narrow screens template editing is read-only; execution status and approvals remain usable
  on mobile (04 §5).

## Blocked by

0.4, 0.6, 0.10, 0.12, 0.16.

Note: the original 15 §2 row listed only 0.6 and 0.12. ADR-0014 adds 0.16 (this UI's entire API
surface) and restores the hidden dependencies on 0.4 and 0.10 that ADR 0010's scope expansion
introduced. Do not start this ticket against unfrozen 0.16 contracts.

## Acceptance criteria

- [ ] `/studio` renders `lang="fa-IR" dir="rtl"` with the eleven navigation entries and Persian
      labels of (04 §2); actions hidden per permission — Seam 3 Playwright + RTL checks (14 §8).
- [ ] Role-aware landing: Technical Maintainer and Viewer land on their (04 §7) focus —
      Seam 3.
- [ ] `/studio/workflows` lists definitions with version status sourced from
      `GET /api/v1/studio/workflows`; no client-side fetch-all filtering (10 §10) — Seam 3 +
      component test.
- [ ] TEMPLATE_READ: published version renders read-only; edit/publish controls absent for
      Viewer; execution mode cannot create or remove semantic nodes — component tests (14 §7).
- [ ] TEMPLATE_EDIT: add/configure node via drag/drop AND via the form alternative; edge
      connection has a source/target form alternative — Seam 3 + accessibility tests (14 §11).
- [ ] Semantic draft save sends `expectedRowVersion` and an idempotency key; layout-only saves
      are debounced separately and hit the layout endpoint — component test asserting request
      payloads (08 §9).
- [ ] Stale `expectedRowVersion` (`WORKFLOW_VERSION_CONFLICT`) stops auto-save and shows a
      server-vs-local diff; never last-write-wins — component test with fixture 409.
- [ ] `Validate` calls the server; findings carry severity/node/rule code and clicking one
      focuses the target node; client hints never mark a workflow publishable (08 §16) —
      component test.
- [ ] Domain-to-canvas adapter maps every node category (07 §2) and every persisted state of the
      repaired enum, including `PAUSED`, `SKIPPED`, `CANCELLED` (ADR-0012), to the (08 §5) visual
      treatment; colour never the sole indicator — adapter unit tests (14 §7).
- [ ] Execution view: loads full snapshot, applies ordered SSE events including `run.paused`,
      `run.resumed`, `run.cancelled`, `run.completed`, `run.failed`, `stage.skipped`,
      `stage.cancelled` and ignores `heartbeat` semantically (ADR-0014); sequence gap triggers
      snapshot refetch; disconnect shows stale/reconnecting and polls — component tests with
      fixture event streams (14 §7).
- [ ] Approval-gate node CTA opens the approval sheet; the only mutation issued is
      `POST /api/v1/core/approval-requests/:id/decisions`; the client cannot transition a run
      from local state (ADR-0013) — component test asserting outgoing requests.
- [ ] Nodes and edges are keyboard-focusable with Persian aria labels; Enter/Space selects,
      Escape clears; structured list alternative shows equivalent state/actions (08 §15) —
      Seam 3 + axe WCAG 2.2 AA (14 §11).
- [ ] Browser refresh and full browser-state loss lose neither the draft definition nor run
      state (ADR 0010, 08 §17) — Seam 3.
- [ ] Every page in scope shows its empty, loading-skeleton, permission-denied,
      configuration-required and failure states (04 §8) — component tests + visual regression
      captures (14 §13).
- [ ] Reduced motion removes animated edges; only the active RUNNING transition animates
      (08 §6) — component test.
- [ ] `pnpm typecheck && pnpm lint && pnpm test && pnpm build` green; `pnpm test:e2e` green for
      the journeys above.
