# Ticket 0.16 — Workflow definition, run-command, SSE and approval APIs

## What to build

The API backbone of Release 0, added by ADR-0014 because the R0 vertical demo (15 §2) requires
an HTTP/SSE/approval/validation band that no ticket previously owned. This ticket is a pure
tracer bullet: with nothing but `curl` and the seeded actors from 0.6, an operator can

1. create a workflow definition and a draft version, mutate it with semantic
   `WorkflowDraftOperation` patches, save layout independently, validate it and publish an
   immutable checksummed version (10 §5, 07 §13);
2. start a run of that version through `POST /runs/:runId/commands` (manifest frozen by 0.11 or
   fail-closed, 07 §6), then pause it, resume it, submit manual input to a
   `manual_fallback: allowed` stage, retry a failed stage, and cancel it — every transition
   conforming to the completed ADR-0012 state machine;
3. satisfy a `minimum_approvals: 2` human gate by two DISTINCT human actors through
   `POST /api/v1/core/approval-requests/:id/decisions` — the single approval write path
   (ADR-0013) — and watch the gate release the run;
4. observe the whole lifecycle on the SSE stream, disconnect mid-run, and resume from
   `afterSequence` without loss or reorder, including the terminal events the original 10 §9
   taxonomy omitted (ADR-0014).

Demoable when done: R0 demo steps 2, 3 and 5 end-to-end from the terminal; ticket 0.13 then puts
the UI on top of exactly these frozen contracts.

Constraints that shape the build:

- Route handlers are thin adapters over shared application services; no business rules in
  handlers (10 §1, 00 §5). Authorization and state transition are checked inside the
  transaction (10 §3).
- The runtime command set is START_RUN, PAUSE_RUN, RESUME_RUN, CANCEL_RUN, RETRY_STAGE,
  SUBMIT_INPUT, CREATE_RERUN and the governed manual skip. The 07 §12 gate verbs
  (APPROVE_GATE, REQUEST_CHANGES, ESCALATE_GATE) are removed per ADR-0013; escalation is the
  approval policy's `escalation_behavior` on the approvals surface (11 §6).
- Event payloads carry safe summaries and IDs, never raw AI responses (10 §8.1); Persian
  messages are presentation-safe, error codes stay stable English identifiers (10 §2).
- This document derives from the bundle and repairs it only where the numbered ADRs record the
  repair; where 07/10 conflict with ADR-0012/0013/0014, the ADRs govern.

## Acceptance criteria

- [ ] Definition lifecycle happy path: create → semantic ops → validate → publish; a published
      version rejects further draft PATCH, layout PUT and publish at both HTTP and DB seams —
      Seam 2 + pnpm test:db.
- [ ] Every 07 §13 publish check is implemented server-side and each has a failing fixture
      (missing start/end, orphan, illegal cycle, unresolved schema, missing gate policy,
      inactive registry reference per ADR-0015, wrong machine order, missing budgets/retry,
      missing Persian message/aria keys, unreachable failure terminal) — workflow definition
      test suite (14 §5).
- [ ] Layout PUT uses its own row version: a layout-only save and a concurrent semantic edit do
      not spuriously conflict; a semantic conflict returns WORKFLOW_VERSION_CONFLICT (10 §5) —
      Seam 2.
- [ ] Mutating requests without Idempotency-Key or expectedRowVersion (where required) are
      rejected; an exact duplicate command replays the recorded result without a second
      transition (10 §3, 07 §7) — Seam 2.
- [ ] START_RUN freezes the 0.11 manifest atomically or fails closed with no partial run
      (07 §6) — Seam 1.
- [ ] PAUSE_RUN from RUNNING, READY and QUEUED yields PAUSED; RESUME_RUN returns the run to its
      eligible pre-pause dispatch state; PAUSE_RUN on SUCCEEDED/FAILED/CANCELLED is rejected
      typed (ADR-0012) — state-transition matrix at Seam 2.
- [ ] CANCEL_RUN reaches CANCELLED from every non-terminal run state; terminal states reject;
      in-flight cancellable work observes the abortSignal path (07 §5) — Seam 1 + Seam 2 matrix.
- [ ] SKIPPED is produced by a condition-false edge and by the capability-gated manual skip; an
      actor without the capability is rejected (ADR-0012) — Seam 1 + Seam 2.
- [ ] Run-level status is computed by the ADR-0012 stage-to-run aggregation rule; a table-driven
      test maps stage-state combinations (incl. WAITING_INPUT and WAITING_APPROVAL cases) to the
      nine-value run enum — state-transition tests.
- [ ] Missing provider yields WAITING_INPUT with reason code PROVIDER_CONFIGURATION_REQUIRED,
      not a global failure (ADR-0012, 11 §7) — Seam 1.
- [ ] SUBMIT_INPUT satisfies an automated stage only when the published definition flags
      manual_fallback: allowed; otherwise rejected (ADR-0012) — Seam 1.
- [ ] APPROVE_GATE, REQUEST_CHANGES and ESCALATE_GATE submitted as run or stage commands are
      rejected with an error whose nextPermittedActions points to the approvals endpoint
      (ADR-0013) — Seam 2.
- [ ] An approval decision by a MACHINE or SERVICE actor is rejected regardless of role
      (ADR-0013) — Seam 2 security test.
- [ ] minimum_approvals: 2 cannot be satisfied by one actor deciding twice: rejected at the
      endpoint AND by the DB distinct-actor constraint (ADR-0013) — Seam 2 negative +
      pnpm test:db.
- [ ] DISTINCT_REVIEWER_REQUIRED blocks the subject creator by actor identity, not session or
      role label; SELF_APPROVAL_ALLOWED decisions are explicitly labeled in the recorded event
      (11 §6.1) — Seam 2.
- [ ] A decision pins the exact subject version; a decision against a stale subject version is
      rejected (14 §4) — Seam 2.
- [ ] SSE drill: a synthetic run driven through pause → resume → skip → approval → cancel and a
      second run through completion and failure emits run.started, run.paused, run.resumed,
      stage.skipped, stage.cancelled, run.cancelled, run.completed and run.failed with
      monotonically increasing per-run sequence; heartbeat arrives within the configured
      interval; reconnecting with afterSequence replays exactly the missed ordered events; a
      forced gap is recoverable via graph snapshot (ADR-0014, 10 §8) — Seam 2 SSE tests.
- [ ] Failed runs are visible via the run list/detail APIs with per-stage states (ADR-0011
      restored exit criterion) — Seam 2.
- [ ] Error envelope: Persian presentation-safe message, stable English code, diagnosticId, no
      internal detail leakage (10 §2, 10 §12) — Seam 2.
- [ ] `pnpm typecheck && pnpm lint && pnpm test && pnpm test:db && pnpm build` green.
