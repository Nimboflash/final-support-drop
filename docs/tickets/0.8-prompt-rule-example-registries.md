# Ticket 0.8 — Prompt, Rule, Example and Constitution registries with governed publish flows

## What to build

The four load-bearing registries that every run manifest freezes (07 §6), as real versioned
PostgreSQL tables with governed publish flows — the repair recorded in ADR-0015 for the review
finding that manifests were required to freeze registries that had no specified storage.
Constitution versions give `programs.constitution_version_id` its FK target. Rule-set versions
carry per-rule provenance, and the only road from a `candidate_rule` (`DRAFT|OBSERVING`, 06 §4)
to an active published rule runs through a Guardian-decided approval on the single approval write
path from ticket 0.6 (ADR-0013, 11 §5) — nothing auto-activates. Prompt versions are published
under the `PROMPT_CONFIGURE` capability with a content scan that rejects credential patterns
(12 §5). The example registry stores accepted, rejected and borderline outputs with reasons.

Publishing is one shared mechanism: DRAFT → PUBLISHED flips immutability on at all three 06 §11
layers and stores a checksum (11 §13). A version resolver service replaces 0.7's fixture
resolvers so that manifest freezing now resolves real constitution/rule/prompt/example versions
— and still fails closed when any is missing. The same resolver returns executor/validator
identity as code-version + checksum (ADR-0015) for manifest recording. Two seed sets land as
versioned configuration: Brand DNA v3.0 rule set v1 (including the food/drink parity rule from
the recorded reconciliation, 17 §3) and the R0 mock prompt set, published under the seeded
dev-Guardian actor (00 §7). This directly restores the R0 exit criterion that prompt versions
come from configuration, not code (ADR-0011).

No HTTP surface ships here: registries are consumed in-process by the pipeline and inspected
through frozen run manifests (0.11/0.16, ADR-0014). Per ADR-0014, ticket 0.11 now depends on
this ticket, because run-manifest freezing without real registries proves nothing.

**Demoable when done:** a seed-and-script session shows a draft rule promoted through a real
Guardian approval into published rule-set v2, a mock run whose frozen manifest cites exact
constitution/rule/prompt/example versions and executor checksums, and a re-run after bumping the
published prompt version freezing the new version with zero code change — while deleting a
version reference makes run creation fail closed.

- **0.7** — manifest freeze and the fixture-resolver interface this ticket replaces.

  rejected at the service seam, and by DB trigger on direct SQL (06 §11); drafts remain editable.
  — `tests/integration/registries/publish-immutability.spec.ts` +
  `tests/db/registries/triggers.spec.ts`, `pnpm test`, `pnpm test:db`.
- [ ] **AC2** (ADR-0015) A program row referencing a nonexistent constitution version violates the
  FK; referencing constitution v1 succeeds. — `tests/db/registries/constitution-fk.spec.ts`,

  `pnpm test`.
